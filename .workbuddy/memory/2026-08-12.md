- 【推送失败根因·已彻底定位】多次 push 报 `Error in the HTTP2 framing layer` / `CONNECT tunnel failed, response 502`。实测：
  - 环境所有出网 HTTPS 经沙箱本地代理 `HTTPS_PROXY=http://127.0.0.1:50655`（osxkeychain 之外真正的出网通道）。
  - 该代理对 `CONNECT github.com:443` 返回 **502 Bad Gateway**（git 推送用的主机）；而 `api.github.com` 经同一代理可达（HTTP 200），说明是代理对 github.com 的 git 主机的白名单/拦截策略，非偶发。
  - 直连（--noproxy）`github.com` 超时无路由；直连 `api.github.com` 反而是通的。
  - 结论：**当前执行环境无法触达 github.com 的 git 端点，与凭证无关**。早前偶见的 `Invalid username or token` 是另一时段代理恰好放行 github.com 时的表现，不能直接证明钥匙串 token 有效。
  - 处置：推送必须在用户本机（github.com 可达的终端）执行 `git push origin main`；本沙箱内即使凭证正确也推不出去。另：钥匙串里的 GitHub token 仍可能过期，需用户本机推送失败时再排查。
