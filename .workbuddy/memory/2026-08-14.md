.btn-outline { color: var(--accent-10); border-color: var(--accent-10); }  /* 行 3361 */

## GitHub 贡献热力图修复

用户报"github 活跃度热力图目前显示不正常"。

- **根因**：`build.js` 的 `buildContributionSvg` 把 GitHub GraphQL 的 `day.weekday` 当作 0-6 整数用于 `y = topPad + row * step`。但 GraphQL 里 `ContributionDay.weekday` 是 `DayOfWeek` **枚举字符串**（"SUNDAY"…"SATURDAY"），不是数字 → `row * step` = `NaN` → 所有 `<rect y="NaN">` 不渲染 → 线上热力图整片空白。
- **模拟复现**：用真实的 GraphQL 返回形状（含 `weekday: "SUNDAY"` 枚举）跑旧逻辑 → **371/371 个 rect 的 y 都是 `NaN`**；改用 `new Date(day.date + 'T00:00:00').getDay()` 后 0 NaN，y 序列为 22,39,56,73,90,107,124（行 0-6 对应周日→周六），并随列换行。
- **修复**（`build.js:1109-1115`）：`const row = new Date(day.date + 'T00:00:00').getDay(); // 0=Sun .. 6=Sat`。
  - 选 `getDay()` 而非数组下标：因为 `contributionDays` 的首尾周可能是部分周（仅含范围内日），下标≠行；用日期本身的星期几最稳。

**方法学**：
- GraphQL **枚举字段在 JSON 响应里是字符串**（枚举名），永远不要当数字用——直接 `getDay()` 从日期派生星期几最稳，且不受 API 字段类型变化影响。

- 找"线上空白"bug 时，把 SVG 关键数值（`y`/`x`/`width`）用正则 `match` 出来断言，能瞬间区分"未渲染"（NaN）vs"渲染但样式错"（数字但样式问题）vs"数据没取到"（svg 为空）。
